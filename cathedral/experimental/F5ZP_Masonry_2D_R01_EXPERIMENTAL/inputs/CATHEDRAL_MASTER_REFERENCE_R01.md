## Part 5 — Technical Standards
*Original: `TECHNICAL_STANDARDS.md`*

# Cathedral Technical Standards — R01

**Status:** reference standard for experimental work, not a change to approved architecture.

## Universal
- Always identify baseline version, units, coordinate system, transformations, calibration and all protected constraints before an edit.
- Architectural work uses true 1:1 scale; historical raster pixels are **not** architectural units without measured calibration.
- Preserve source artifacts; write distinct, versioned experimental outputs and a reproducible command/config record.
- Never assume newest file is authoritative. Preserve authoritatively generated models and the generator/input pair.

## 2D measurement and drawing
- Preserve original plate bytes and crop/page transformations; optionally record SHA-256 hashes.
- Store arcs as centers, radii, endpoints/angles, direction, tangency and error estimates; store source sample points and calibration.
- Report RMS/max residual where meaningful, including evidence limits, and distinguish actual engraving strokes from modernized ideal geometry.
- SVG layers: **black solid** confirmed contours; **thin dashed gray** axes and construction; **red dashed** conjectural geometry.
- Annotate physical units only when calibration supports them; do not create fake depth or stone profiles from an uncalibrated engraving.
- Generated illustration/PNG is not a CAD source or historical geometric proof.

## 3D and architectural relationships
- GLB default; STL upon request or necessity. Preserve distinct objects, useful materials, dimensions, location, and orientation.
- Validate mesh bounds, degenerate faces, coordinate transforms, continuity/intersections, export/import integrity and units.
- Geometry shared between arch, rib, vault web, respond, pier and support must remain coordinated.
- For arch-to-respond transitions, test true tangent and vertical termination rather than bending/fanning geometry.
- Isolate the requested change and compare all unaffected component dimensions and connections with known-good saved outputs.

## Validation labels (not interchangeable)
1. **Technical:** script executes, files parse/open, deterministic output where expected.
2. **Geometric:** dimensional/coordinate tolerances, continuity, contact and fit checks pass.
3. **Architectural:** details align with approved bay and springing relationships.
4. **Historical:** construction is actually supported by traceable source evidence.
5. **Structural:** load path, eccentricity, masonry capacity, support conditions assessed by appropriate structural evidence; *collision-free is not structural sign-off*.

## Release gate
- Record actual test commands, results, numerical tolerances, images/overlays and failures; never claim tests not run.
- Preserve approved baseline; experimental result stays experimental even if technically valid.
- A proposed promotion into approved architecture requires explicit user acceptance.
